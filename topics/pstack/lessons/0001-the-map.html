Lesson 1 · pstack

The Map: One Router, Twenty-Three Playbooks

You state the goal. The playbook supplies the rigor.

Your win for this lesson

You can install pstack in Claude Code and set it up for a Claude-only subscription, knowing what that costs you. You can also trace what happens to a /pstack:poteto-mode prompt from the moment you send it.

pstack is a set of agent skills by Lauren Tan (handle poteto), who works on the React core team and ships code at Cursor. It lives in Cursor's official plugin repo under the MIT license.[1] She states the aim plainly: "pstack helps you write less, but higher quality code." Her answer to slop is: "if you want to go fast, go deep first."[2]

1. Idea one: one front door, many playbooks

You don't call pstack's skills in order yourself. You call one router, poteto-mode, and it does the sequencing. Here is what happens to a prompt:[3]

  1. Restate. The agent's first message gives your goal, the problem, and the smallest change it expects, in its own words. It doesn't wait for you to confirm.
  2. Read the principles. It reads an index of 24 one-line engineering rules, such as Laziness Protocol and Prove It Works.
  3. Match a playbook. A defect goes to Bug fix, new behavior to Feature, and a read-only question to Investigation. Large work, or work you'll leave running, goes to figure-it-out, which writes a custom playbook.
  4. Open a todo list. The playbook's steps are copied in word for word. A step it decides not to do stays in the list as skip: <reason>.
  5. Run the steps. Each step calls the skills it needs (how, architect, tdd, interrogate…) and hands coding to poteto-agent subagents. The main chat keeps the lead.
  6. Verify on the real surface. It checks where the problem appeared. "Inconclusive" doesn't count as a pass, and neither does a check on the wrong surface.
  7. Open a PR. Every code playbook ends with Opening a PR: work in a worktree off main, keep commits small, and open a ready PR with gh.

The 23 playbooks fall into five families:[2]

UnderstandInvestigation, runtime forensics, trace forensicsUnderstanding code

Contrast with Pocock

Pocock's flow puts the plan first: grill, then spec, then tickets. poteto ships no planning skills: "i don't believe in planning. the best spec is code."[2] pstack's rigor comes in at other points: a restatement up front, playbook steps, multi-model review and proof on the real surface. Lesson 8 compares the two in full. For now, notice where each one spends its effort.

2. Idea two: setting it up on Claude only

You asked whether Cursor or Grok would be better. Short answer: start in Claude Code. You don't need either one to use pstack well. Here's why, and what you give up.

What changes. pstack's defaults split work between model families. Code delegates go to Grok, and judgment and prose go to Opus. The review panels (arena, architect, interrogate) default to one Opus plus one Grok.[4] The Claude Code adapter turns any non-Claude slug into "omit model so the agent runs on the session model."[5] So on a Claude subscription, everything still runs, but every role is Claude.

What you lose. Model diversity in the review panels. poteto-mode's rule is: "A second opinion is the same prompt against a different model. Agreement is high-signal."[3] When both reviewers are Claude, their agreement means less, because they tend to share the same blind spots. That last point is my inference, not a measured result.

What you keep. Almost everything else: routing, playbooks, principles, verification on the real surface, subagent discipline, and the PR hygiene. Those don't depend on which vendor's model runs.

The other cost is tokens. pstack "spends extra tokens on subagents and review panels. That's the price of the rigor."[6] On a subscription, that means hitting your usage limits sooner. Pick a medium budget to start, and save poteto-mode for work that needs rigor.

When to reconsider Cursor: after several real runs, if you find /interrogate panels agreeing on findings that later turn out wrong. That would be evidence that diversity matters for your work. Until then, paying for it is speculative.

The setup procedure

  1. /plugin marketplace add cursor/plugins
  2. /plugin install pstack@cursor-plugins[2]
  3. Optional: /plugin → Marketplaces → cursor-plugins → Enable auto-update. Claude Code leaves auto-update off for third-party marketplaces.
  4. /pstack:setup-pstack. Pick a budget, then accept the roles. Grok roles become inherit-parent. It writes ~/.claude/rules/pstack-models.md, which Claude Code loads into every new session.[5]
  5. When it offers create-verification-skill, say yes. The guide says that "of everything in this guide, the verification skill pays off the most."[6]
  6. Start a new session. The model rule only applies to new sessions.

3. Idea three: a solo repo still gets a PR

Every code playbook ends with Opening a PR: a worktree off main, small ordered commits, a Conventional Commits title, and a PR body with ## Why, ## Scope and ## Verification. The PR opens with gh, marked ready.[7] pstack assumes a team. Flavio Copes notes that solo projects pushing to main "should say so in the prompt."[8] You have two options:

  • Keep the PR (recommended when the repo has a GitHub remote). Merge it yourself. The PR body is a one-minute briefing that shows what changed and how it was proved. That's your review checkpoint, even working alone.
  • No PR. Add "solo repo, no PR: commit on a branch and stop" to the prompt. Do this when there's no remote, or the change is too small to need one.

4. Practice

Recall: the seven stages

Without scrolling up, list what poteto-mode does with a prompt, from receiving it to the end. Then add one line on what changes on a Claude-only subscription.

1. Restate your goal, the problem and the smallest change. 2. Read the principles index. 3. Match a playbook (or figure-it-out). 4. Copy its steps into a todo list, with skips kept visible. 5. Run the steps, calling skills and handing code to poteto-agent subagents. 6. Verify on the real surface. 7. Open a PR.

On Claude only, every role runs on Claude, so the review panels lose a second model family. Everything else works the same.
