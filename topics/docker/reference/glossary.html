Docker for Kubernetes · Reference

Glossary

Lessons use these words in exactly these senses. The "In Kubernetes" notes point forward to the Kubernetes Topic.

Images

Image
A read-only package of the files, libraries and default settings an app needs, built as a stack of layers. It never changes after it is built; a change means a new image. In Kubernetes: a Pod's container names the image to run.
Layer
One set of file changes (added, changed, deleted) in an image. Layers are shared between images and containers that use them.
Image reference
The name you type, repository:tag, such as alpine:3.20. With no tag, Docker assumes :latest, which is just a default tag name, not "the newest".
Registry
A server that stores images so they can be pulled elsewhere, such as Docker Hub. docker run pulls a missing image from it automatically.

Containers

Container
An isolated process started from an image, plus its own thin writable layer. Many containers can share one image.
Writable layer
The container's private top layer, where every file it writes or deletes is recorded. It survives stop and start, and is deleted when the container is removed. docker diff shows it.
Main process (PID 1)
The command a container runs: the image's default, or the one you put after the image name. The container is running exactly while this process runs. docker stop sends it SIGTERM, then SIGKILL after a grace period (10 seconds by default).
Running / Exited
The two states you'll see most. Exited containers still exist, with their writable layer, until removed. docker ps shows running containers only; docker ps -a shows all of them. In Kubernetes: a crashed container is restarted with a clean state, not resumed.
Immutable container
The practice of never patching a running container: build a new image, then replace the container.

Runtimes and standards

Docker Engine
The daemon that builds images and runs containers on your machine. The docker command is its client.
Container runtime
The software that actually runs containers. Docker Engine uses containerd underneath. In Kubernetes: nodes talk to a runtime such as containerd or CRI-O through the CRI, not to Docker Engine.
OCI
Open Container Initiative: the standard formats for images and for running containers. They are why an image built with Docker runs on any Kubernetes node.
