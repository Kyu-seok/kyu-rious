The minimal Java service

FROM eclipse-temurin:21-jdk    # base image; -jdk has javac, -jre only runs Java
WORKDIR /app                   # created if missing; later paths are relative to it
COPY App.java .                # from the build context into /app
RUN javac App.java             # runs at build time, saved as a layer
EXPOSE 8080                    # documentation only
CMD ["java", "App"]            # default command at run time, exec form

Instructions

InstructionHappens atRemember
FROMBuildMust be first. Pin a tag, such as 21-jdk.
WORKDIRBuildUse it instead of RUN cd …. Also the container's working directory.
COPYBuildSources are relative to the build context, never outside it.
RUNBuildMust finish. Never start the service here.
EXPOSERecordedDoesn't publish. Use docker run -p.
CMDRunOnly the last one counts. Replaces the base image's CMD. Overridden by a command after the image name in docker run, or by args in Kubernetes.

Exec form vs shell form

WrittenCMD ["java", "App"]CMD java App
Actually runsjava App/bin/sh -c "java App"
PID 1JavaThe shell
docker stopJava gets SIGTERM, exits fast: Exited (143)Signal ignored, killed after 10 s: Exited (137)
Use forCMD, alwaysRUN, where shell features like && help

Exit codes above 128 mean "killed by a signal": 128 + 15 (SIGTERM) = 143; 128 + 9 (SIGKILL) = 137.

Common mistakes

  • RUN java App: the build hangs, because a server never finishes.
  • COPY before WORKDIR: the file lands in the base image's working directory, not /app.
  • A -jre base with RUN javac: javac doesn't exist there.
  • Single quotes in exec form, CMD ['java', 'App']: that isn't valid JSON, so Docker silently treats it as shell form and runs /bin/sh -c "['java', 'App']".
