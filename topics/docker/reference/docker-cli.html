Container lifecycle

            docker run  (= create + start)
image ─────────────────────────────▶ running
                                       │  main process ends, or docker stop
                                       ▼
          docker start / restart ◀── exited   (writable layer kept)
                                       │  docker rm
                                       ▼
                                     gone     (writable layer deleted)

Running

CommandWhat it does
docker run IMAGE [CMD…]Pull the image if it is missing, create a container, start its main process. A command after the image replaces the image's default.
-dRun in the background and print the container ID.
--name NGive it a name you choose. Names must be unique, even among exited containers.
--rmRemove the container as soon as it exits. Good for one-off commands.
docker exec N CMD…Run an extra command inside a running container. Use sh -c '…' when the command has >, ; or $VAR.

Looking

CommandShows
docker ps / docker ps -aRunning containers / all containers, including exited ones
docker imagesImages stored locally
docker diff NThe writable layer: A added, C changed, D deleted
docker logs NWhat the main process printed to stdout and stderr
docker top NThe processes running inside

Stopping and cleaning up

CommandEffect
docker stop NSIGTERM, wait 10 seconds, then SIGKILL. The container and its writable layer remain.
docker start NRun the same main process again in the same container, with earlier changes intact.
docker rm N / rm -f NDelete a stopped container / stop and delete a running one. Its writable layer is gone.
docker rmi IMAGEDelete an image. Refused while any container, even an exited one, uses it.
